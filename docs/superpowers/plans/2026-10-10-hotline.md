# Hotline — piano di implementazione

> **Per gli esecutori:** usare superpowers:subagent-driven-development (consigliato) o superpowers:executing-plans, compito per compito. I passi usano la sintassi `- [ ]`.

**Obiettivo:** plugin VST3 stereo con sei dispositivi (megafono, telefono, walkie-talkie, radio AM, PA, altoparlante economico), Morph automatabile, latenza zero.

**Architettura:** una catena unica parametrica (banda, drive, cono, crush, compander, rumore, room); ogni dispositivo è una riga di una tabella e Morph interpola dal neutro a quella riga. Motore puro (senza SDK), come `engine.h` di Pillow Talk; processor e controller VST3 sottili; editor VSTGUI con i controlli di `shared/ui`.

**Stack:** C++20, VST3 SDK, VSTGUI4, `fairy_ui` / `fairy_ui_widgets` (`shared/ui`). Il kit grafico comune è già in `shared/ui` (`RackKnob`, `RackToggle`, `RackLitChoice`, `MeterBar`, `ClipLed`, usura, viti, nastro, `back_panel.h`, `routing.h`). Struttura di riferimento: `src/pillow-talk` (CMake, params/state/engine, test con macro `ASSERT_*`/`RUN_TEST`) e `src/the-stripper/src/ui` (layout, editor, meter).

**Spec:** `docs/superpowers/specs/2026-10-10-hotline-design.md`. Preview: `src/hotline/docs/mockups/hotline_rack.html`.

## Global Constraints

- I/O stereo (2 in, 2 out); **latenza zero** (nessun oversampling, nessun lookahead).
- Nessuna allocazione nel thread audio (come i test di Pillow Talk: contatore su `operator new`); protezione dai denormali.
- ID dei parametri **congelati** da subito: 11 parametri, ordine fisso (Task 1). Stato versione **1**: `int32 version` + `kNumParams` double little endian (formato di `pillow-talk/src/state.h`). Versione sconosciuta, dati corti o valori non finiti: stato ignorato, restano i default.
- Il Bypass lascia passare il segnale **identico bit per bit** a regime.
- Morph = 0: uscita uguale all'ingresso entro 1e-6 (blocchi neutri saltati esattamente).
- Il cambio di Device è un crossfade di circa 40 ms (parametri smussati, nessuno scatto).
- Testo visibile dell'editor in **inglese**; identificatori, commenti e commit in inglese; documenti in italiano.
- Materiale e texture dell'editor sono quelli di The Stripper (alluminio nero, grana fine): niente scelte per plugin.
- Il **retro** ha le schede SETTINGS, DEVICES, ROUTING e CREDITS (ordine dei link del design system); la scheda DEVICES è generata dalla stessa tabella usata dal motore; ROUTING è lo schema a blocchi del §4 della spec.
- Build in una cartella scratch fuori dal repo, `-j2`, solo i target necessari. Commit `tipo(hotline): descrizione` con la riga di co-autore dell'ambiente; in stage solo i file propri, per nome. Nessun cambio ai submodule.
- Comandi (da usare in ogni compito):
  - configura (una volta): `cmake -S . -B /tmp/hotline-build -DCMAKE_BUILD_TYPE=Release -DGPU_NAM_DISABLE_CUDA=ON`
  - test: `cmake --build /tmp/hotline-build -j2 --target hotline_tests && /tmp/hotline-build/src/hotline/hotline_tests`

## Decisioni di progetto fissate dal piano

Il piano le fissa dove la spec è muta; sono già riportate nella spec (§2.1).

- **Controlli utente.** Drive, Noise e Room moltiplicano il valore del dispositivo per `2·n` (n = 0,5 → ×1; 0 → spento; 1 → ×2). Tone sposta l'LPF di `(n−0,5)·2` ottave e l'HPF di `−(n−0,5)·1` ottave. Gain = `−20 + 40·n` dB. Mix è dry/wet dell'intero dispositivo.
- **Default (normalizzati):** Device 0, Morph 1, Gain 0,5, Mono 0, Drive 0,5, Tone 0,5, Noise 0,5, Room 0,5, Mix 1, CharacterIn 1, Bypass 0.
- **IN di CHARACTER spento:** Drive, Tone, Noise, Room e Mix vengono ignorati (drive 0, tone 0, noise e room spenti, Mix = 1); restano banda, cono, crush e compander del dispositivo.
- **Mono:** ingresso = `lerp(canale, (L+R)/2, monoMix)` con `monoMix` smussato (10 ms); con Mono attivo le due uscite sono identiche.
- **Valori iniziali dei dispositivi** (da regolare a orecchio, Task 2):

| Device | HP Hz | LP Hz | Drive | Cono Hz / dB / Q | Horn dB | Crush Hz / bit | Comp ratio / squelch dB | Noise dB | Room |
|---|---|---|---|---|---|---|---|---|---|
| Megaphone | 400 | 4500 | 0,5 | 1800 / +6 / 2,0 | +4 | 192000 / 24 | 3 / −120 | −60 | 0,05 |
| Telephone | 300 | 3400 | 0,25 | 1200 / +3 / 1,0 | 0 | 8000 / 10 | 2 / −120 | −54 | 0 |
| Walkie-talkie | 400 | 2800 | 0,7 | 1500 / +4 / 1,0 | 0 | 11025 / 8 | 6 / −50 | −40 | 0 |
| AM radio | 150 | 5000 | 0,3 | 900 / +2 / 0,8 | 0 | 192000 / 24 | 2 / −120 | −48 | 0 |
| Station PA | 250 | 6000 | 0,2 | 2500 / +4 / 1,5 | 0 | 192000 / 24 | 2 / −120 | −66 | 0,6 |
| Cheap speaker | 180 | 7000 | 0,4 | 1100 / +5 / 3,0 | 0 | 192000 / 24 | 1 / −120 | −70 | 0 |

Neutro: HP 20, LP 20000, drive 0, cono 1000 / 0 / 1, horn 0, crush 192000 / 24, comp 1 / −120, noise −120, room 0.

## Review Focus

Ingressi che la spec non nomina e che più probabilmente rompono qualcosa (ognuno ha un test nel compito indicato):

1. **Sample rate estremi (8 kHz … 192 kHz):** LPF e frequenze del cono limitati sotto Nyquist, niente NaN (Task 3, Task 5).
2. **Blocchi di 0, 1 e più campioni del massimo preparato:** nessun crash, uscita identica a quella a blocchi normali (Task 5).
3. **Traccia mono dell'host (`inR` nullo o uguale a `inL`, `outR` nullo):** uscita valida, canali uguali (Task 5, Task 6).
4. **Morph automatato da 0 a 1 in un solo blocco:** salto massimo tra campioni consecutivi limitato (nessun click) (Task 5).
5. **Cambio di Device con la coda del Room ancora in corso:** nessun salto brusco, nessun NaN (Task 5).

### Task 4: Blocchi DSP — crush, compander, rumore, room

**Files:** Create `src/hotline/src/dsp/crush.h`, `compander.h`, `noise.h`, `room.h`; Modify `tests/test_hotline.cpp`.

**Interfaces:**
- Produces (`namespace FairyTapes::Hotline::DSP`):
  - `class Crush { void prepare(double fs); void set(double rateHz, double bits); float process(float x); void clear(); }`: sample-and-hold a `rateHz` e quantizzazione a `bits`; passa-tutto esatto se `rateHz ≥ fs` e `bits ≥ 24`.
  - `class Compander { void prepare(double fs); void set(double ratio, double squelchDb); float process(float x); void clear(); }`: compressore con soglia −24 dB e rapporto `ratio`; sotto `squelchDb` un gate morbido (guadagno 0 a 10 dB sotto); passa-tutto esatto con `ratio ≤ 1` e `squelchDb ≤ −120`.
  - `class Noise { void prepare(double fs, uint32_t seed); void set(double levelDb); float next(); }`: soffio filtrato più crackle sparso, xorshift deterministico, `levelDb` = RMS totale su 1 s; esattamente 0 con `levelDb ≤ −120`.
