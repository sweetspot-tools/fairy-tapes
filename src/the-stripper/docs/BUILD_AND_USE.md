# The Stripper — Build, install, and use

How to build the plugin, install it in Reaper and use the editor.

---

## 1. Build (from repo root)

Sources with the submodules the build needs (VST 3 SDK with VSTGUI, NeuralAmpModelerCore with its dependencies); `vendors/airwindows` and `vendors/dusk-audio-plugins` are reference only (`update = none`) and are not needed. See [Getting the sources](../../../README.md#getting-the-sources).

```bash
git clone --recurse-submodules https://github.com/sweetspot-tools/fairy-tapes.git
cd fairy-tapes
# already cloned without submodules: git submodule update --init --recursive
```

Configure from the repo root (the plugin needs `shared/` and the SDK targets set up by the root `CMakeLists.txt`) into a build folder **outside** the repository, and build only the targets you need:

```bash
cmake -S . -B ../fairy-tapes-build -DCMAKE_BUILD_TYPE=Release -DGPU_NAM_DISABLE_CUDA=ON
cmake --build ../fairy-tapes-build --config Release --target the_stripper the_stripper_tests -j2
ctest --test-dir ../fairy-tapes-build -C Release -R the_stripper_tests --output-on-failure
```

`bash build.sh the-stripper` also works (it runs the tests first, then builds the plugin) but it uses `build/` inside the repository.

**Output:** `dist/TheStripper.vst3/` in the repo root (the folder is the plugin bundle). The build writes the bundle directly to `dist/`.

---

## 2. Install in Reaper (Linux example)

1. Find your VST3 path. Common locations:
   - Linux: `~/.vst3` or `/usr/lib/vst3`
   - Reaper can also scan a custom folder (Options → Preferences → VST).

2. Copy the **entire** bundle:
   ```bash
   cp -r dist/TheStripper.vst3 ~/.vst3/
   ```

3. In Reaper: **Options → Preferences → Plug-ins → VST** → (re)scan or add path if needed.

4. Insert the plugin on a track: **Insert → FX** → search "The Stripper" or "Fairy Tapes".

5. The plugin opens its own editor (1000 × 628, drawn by the code). The host's generic parameter list also works.

---

## 3. Using it

- **Strip Mode (CHAN / BUS):** Channel = 4K-EQ Black + Multi-Comp (Voice / Drums / Classic), Drive block right after the input; Mix bus = 4K-EQ Brown + Multi-Comp Bus, Drive block before the limiter. The Voice/Drums/Classic buttons only exist in Channel mode.
- **IN buttons:** each module (filters share one, EQ, compression, drive, limiter, gate) has an IN button; lit = in the signal path. BYPASS (Output box) bypasses everything.
- **Drive:** two engines in series, NAM then TAPE, each with its switch. Click the paper strip in the Drive box to pick a `.nam` model (model browser: add folders, search, LOAD; NO MODEL unloads it and the NAM passes the signal through). The model path is saved in the project. Models are loaded by hand from local folders: no online catalogue (Tone3000) in version 1.
- **Meters:** Level box (input/output peaks, gain reduction, one clip LED per stage; a click on a LED clears them all).
- **Reset:** double-click a knob to return to its default.
- Gain staging is inert (no control); Limiter and Gate are Airwindows ports (BlockParty, DeNoise).

## 4. Developing

- Build in a scratch folder (the disk of the repo is small): `cmake -S . -B /tmp/ft-build -DCMAKE_BUILD_TYPE=Release -DGPU_NAM_DISABLE_CUDA=ON && cmake --build /tmp/ft-build --target the_stripper the_stripper_tests -j2 && ctest --test-dir /tmp/ft-build -R the_stripper_tests`. The header-only test targets (`the_stripper_state_tests`, `the_stripper_layout_tests`, ...) are built only when named; the module tests (`the_stripper_factory_test`, ...) load the bundle from `dist/` and are skipped when it is missing.
- **Linux dependencies of VSTGUI:** the X11/Cairo/Pango/fontconfig development packages (same list as `.github/workflows/build.yml`).
- Offscreen preview of the editor, no host needed: `cmake --build /tmp/ft-build --target the_stripper_render` then `the_stripper_render out.png [bypass] [bus] [eq-off] [nam-off] [tape-off] [recall] [moved] [meters] [seed=<n>] [model=<file>] [gpu] [model-error=<text>] [browser] [back-settings|back-buttons|back-routing|back-credits]` (list in `tools/render_editor.cpp`).
- The panel grain tile `shared/ui/assets/panel_grain.png` (common to the suite) is generated by `tools/gen_panel_grain.py` (NumPy, Pillow; tests: `python3 -m pytest src/the-stripper/tools`).
- GPU path of the NAM: leave out `-DGPU_NAM_DISABLE_CUDA=ON` on a machine with the CUDA toolkit; not verified yet. See `shared/gpu_nam/docs/GPU_NAM_ARCHITECTURE.md`.
